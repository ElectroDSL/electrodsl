# ElectroDSL 0.6 production workflow

ElectroDSL 0.6 turns a group of schematic sources into a reproducible production documentation set.

## Project manifest

Place `electrodsl.json` beside the `.edsl` sources. The manifest identifies the project, source files, output directory, and whether reports are required. Paths are restricted to the project directory.

```json
{
  "schema": "electrodsl-project/0.6",
  "name": "Motor Panel",
  "version": "1.0.0",
  "language": "0.6",
  "circuits": ["supply.edsl", "control.edsl"],
  "output": { "directory": "build", "format": "svg" },
  "reports": true
}
```

## Build and verify

```powershell
node packages/cli/dist/index.js project build examples/project-v06
node packages/cli/dist/index.js project verify examples/project-v06
```

The build creates one SVG per source, JSON and CSV reports for the bill of materials, conductors, cables, terminals, and cross references, plus `artifacts.json`. The artifact manifest records deterministic SHA-256 digests for every input and output. Verification fails when a source or generated artifact is missing or changed.

For one source, `edsl report design.edsl --output reports` generates the same report formats without a project manifest.

## Compatibility

Version 0.6 retains the 0.1–0.5 language constructs. Its additions are the project-level build contract and production reports; the schematic grammar remains backward compatible.
