# ElectroDSL Language Specification 0.3

Status: Stable specification for the 0.3 release.

## 1. Scope

ElectroDSL is a UTF-8, text-based language for describing electrical schematic connectivity. Version 0.3 standardizes source formatting, diagnostics, and a canonical JSON intermediate representation (IR). Drawing preferences are explicitly non-electrical.

The keywords `EDSL`, `PROJECT`, `CIRCUIT`, `COMPONENT`, `JUNCTION`, `NET`, and `CONNECT` are case-sensitive. Whitespace is insignificant except inside quoted strings.

## 2. Grammar

The following EBNF is normative. `identifier` matches `[A-Za-z_][A-Za-z0-9_-]*`; `terminal` is an identifier or one or more decimal digits; `string` is a double-quoted string.

```ebnf
document    = "EDSL", version, project ;
version     = "0.1" | "0.2" | "0.3" ;
project     = "PROJECT", string, "{", { circuit }, "}" ;
circuit     = "CIRCUIT", string, "{", { statement }, "}" ;
statement   = component | junction | net | connection ;
component   = "COMPONENT", identifier, ":", identifier, "{", { property }, "}" ;
property    = identifier, "=", string ;
junction    = "JUNCTION", identifier, ";" ;
net         = "NET", identifier, ( ";" | "{", { endpoint, [ ";" ] }, "}" ) ;
connection  = "CONNECT", endpoint, "->", endpoint,
              ( ";" | "{", "route", "=", route, [ ";" ], "}" ) ;
endpoint    = identifier, [ ".", terminal ] ;
route       = '"auto"' | '"above"' | '"below"' ;
```

## 3. Electrical semantics

- A component identifier is unique within its circuit.
- A component endpoint contains a valid terminal declared by its component type.
- A junction endpoint is the junction identifier without a terminal.
- `CONNECT A -> B` declares bidirectional electrical continuity between its endpoints. Arrow direction has no electrical meaning.
- All members of a named `NET` are electrically continuous. A populated net contains at least two unique members.
- Net names are unique within a circuit.
- Connectivity is independent of declaration order and presentation preferences.

## 4. Presentation semantics

`route` is a non-electrical hint. `auto` delegates routing to the renderer; `above` and `below` request an outside channel on that side. A renderer may adjust a requested route to prevent collisions, but it must not change connectivity.

## 5. Canonical JSON IR

The canonical IR schema identifier is `https://electrodsl.org/schema/ir/0.3`. Object field order is not semantically significant. Electrical data is stored under `electrical`; optional drawing choices are stored under `presentation`. Consumers must ignore unknown fields to permit compatible extensions.

The reference implementation exports it with:

```powershell
node packages/cli/dist/index.js export design.edsl --format json
```

## 6. Diagnostics

Diagnostic codes are stable identifiers. Syntax diagnostics include a one-based line and column when available.

- `E1000`: unrecognized source character
- `E1001`: grammar error
- `E2000`–`E2999`: language-version and semantic errors

## 7. Conformance

An implementation conforms to ElectroDSL 0.3 parsing when it accepts every file under `conformance/accepted` and rejects every file under `conformance/rejected`. A full implementation must additionally emit equivalent canonical IR for accepted documents.

## 8. Compatibility

The reference parser accepts 0.1, 0.2, and 0.3 documents. Version 0.1 documents cannot use net membership, junctions, or route preferences. Version 0.3 does not remove any 0.2 construct.
