# ElectroDSL Language Specification 0.4

Status: Stable specification for the 0.4 release. This document extends, and does not replace, the 0.3 core specification.

## Engineering declarations

```ebnf
project     = "PROJECT", string, "{", { module | circuit }, "}" ;
module      = "MODULE", identifier, "{", { port | statement }, "}" ;
statement   = component | instance | junction | port | net | connection
            | conductor | cable | bus ;
instance    = "INSTANCE", identifier, ":", identifier, ";" ;
port        = "PORT", identifier, ";" ;
conductor   = "CONDUCTOR", identifier, ":", endpoint, "->", endpoint,
              "{", { property }, "}" ;
cable       = "CABLE", identifier, "{", { property }, "}" ;
bus         = "BUS", identifier, "{", { property | endpoint, ";" }, "}" ;
property    = identifier, "=", string, [ ";" ] ;
```

## Typed engineering values

Engineering values remain quoted to keep the grammar deterministic, but the canonical IR includes their parsed dimension and SI-normalized value. The reference implementation supports:

- Current: `A`, `mA`
- Voltage: `V`, `kV`
- Power: `W`, `kW`
- Resistance: `ohm`, `kohm`, `Mohm`
- Capacitance: `F`, `uF`, `nF`
- Inductance: `H`, `mH`
- Frequency: `Hz`, `kHz`
- Length: `m`, `mm`
- Cross-sectional area: `mm2`, `mm²`

Known properties are dimension checked: `voltage`, `current`, `rating`, `power`, `resistance`, `capacitance`, `inductance`, `frequency`, `length`, `size`, and dimensionless `cores`.

## Conductors, cables, buses, and phases

A `CONDUCTOR` declares electrical continuity and carries engineering properties such as cross-sectional `size`, `phase`, color, and cable membership. A `CABLE` describes a physical multi-core assembly. A `BUS` electrically joins all its member endpoints and may declare a comma-separated `phases` property.

Standard phase identifiers are `L1`, `L2`, `L3`, `N`, `PE`, `+`, `-`, `DC+`, and `DC-`. `PE` denotes protective earth.

## Modules and instances

A `MODULE` is a reusable circuit body with named public `PORT` declarations. An `INSTANCE` references a module by name. Instance endpoints use `instance.port`, for example `M1.LINE`. Module names and referenced ports must exist.

## Cross-sheet ports

Circuits declaring the same `PORT` identifier refer to one project-level electrical connection point. This enables cross-sheet continuity without drawing an artificial long wire. A port endpoint has no terminal suffix.

## Reference designations

Components may carry a `designation` property following the functional/location/product structure, for example `=P1+CC1-F1`. The v0.4 validator accepts an optional function aspect (`=`), optional location aspect (`+`), and requires a product aspect (`-`).

## Canonical IR

The v0.4 schema identifier is `https://electrodsl.org/schema/ir/0.4`. Modules, ports, instances, conductors, cables, and buses appear under electrical semantics. Every property retains its source spelling; recognized engineering values additionally contain dimension, SI value, and SI unit.

## Compatibility

The parser continues to accept 0.1 through 0.3. Engineering declarations and modules require an `EDSL 0.4` header.
