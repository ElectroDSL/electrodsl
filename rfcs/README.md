# ElectroDSL RFC Process

Language and canonical-IR changes are proposed through public Request for Comments documents. An RFC is required for new syntax, changed electrical meaning, canonical-IR compatibility changes, or new standard diagnostic families.

1. Copy `0000-template.md` to the next available number.
2. Describe motivation, specification, compatibility, alternatives, and conformance tests.
3. Open a pull request and collect implementation and user feedback.
4. Maintainers record the decision as `Accepted`, `Rejected`, or `Deferred`.
5. Accepted behavior is not released until specification text and conformance fixtures are merged.

Minor fixes, documentation corrections, and implementation changes with no observable language impact do not require an RFC.
